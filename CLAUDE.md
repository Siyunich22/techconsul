# CLAUDE.md — платформа «ТехОценка»

## Что строим
Веб-платформа: загрузка документов инвестпроекта → ИИ-черновик оценки технической проработанности и закупок → проверка экспертами → DOCX/PDF по эталону банка. Полное ТЗ — `TZ.md`. Структура отчёта — `templates/tech_assessment_bank_v1.yaml`.

## Порядок работы
- Работай по фазам из `TZ.md` §12. В начале фазы составь план, в конце прогони `make test` и сверь критерии приёмки.
- Текущая фаза и прогресс → `docs/PROGRESS.md` (обновляй после каждой завершённой задачи).
- Решения и допущения → `docs/DECISIONS.md` (дата, решение, причина).
- Не спрашивай подтверждения на рутинные шаги. Останавливайся только на необратимых действиях (удаление данных, миграции с потерей данных).

## Жёсткие правила
1. **Шаблон — источник истины.** Пункты ТЗ, формулировки, шкалы рисков, обязательные риски — только из YAML. Никакого хардкода id пунктов в коде, кроме тестов.
2. **Нет вывода без источника.** Любой `SectionResult` со статусом `full|partial` без `sources` — ошибка валидации. Для `not_disclosed` обязательны все 4 поля `gap`.
3. **Эксперт — автор.** Выпуск версии `released` невозможен, пока не утверждены все пункты и риски. Не делай обходов «для удобства».
4. **Изоляция организаций.** Каждый запрос к БД фильтруется по `org_id`. Тест на утечку — обязателен.
5. **LLM за абстракцией.** Вызовы Anthropic только через `backend/app/llm/client.py` (ретраи, учёт токенов, prompt caching, моки в тестах). Модели — из конфига: `LLM_MODEL_ANALYSIS=claude-opus-5-5`, `LLM_MODEL_EXTRACT=claude-sonnet-5-5`, `LLM_MODEL_CHEAP=claude-haiku-4-5-20251001`.
6. **Промпты — файлы.** `backend/app/llm/prompts/*.md`, с переменными; никаких промптов строками внутри кода.
7. **Структурированный вывод.** Ответы агентов валидируются Pydantic-схемой; при невалидном JSON — 1 ретрай с ошибкой в контексте, затем статус `failed` для пункта (прогон продолжается).
8. **Файлы неизменяемы.** Загруженные документы и выпущенные версии отчёта не перезаписываются.
9. Тесты не обращаются к реальному API, кроме помеченных `@pytest.mark.live` (запуск при `RUN_LIVE_LLM=1`).

## Стиль текста отчёта (системный промпт агентов разделов)
- Язык — русский, деловой, однозначный. Без «возможно/вероятно» без количественного обоснования.
- Структура пункта: краткий вывод → аргументация с цифрами → таблица (если есть в `output_hints`) → замечания → рекомендации.
- Ссылки на источники в тексте как `[S12]`; источник — документ+страница / лист+ячейки / URL+дата обращения.
- Внешние источники: официальные, независимые, актуальные (госорганы РК, отраслевые ассоциации, производители оборудования, рецензируемые издания). Агрегаторы и блоги — только как вспомогательные.
- Не включай общую информацию, не ведущую к выводу о проекте.
- В поисковые запросы не подставляй наименование Заказчика и проекта (конфиденциальность).

## Команды
- `make up` — поднять окружение; `make down`
- `make test` — backend pytest + frontend lint/typecheck
- `make e2e` — Playwright
- `make seed` — создать демо-организацию и sample_project
- `make migrate` — alembic upgrade head
